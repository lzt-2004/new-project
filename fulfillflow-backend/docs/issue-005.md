# Issue #5：支付确认与订单状态流转

## 目标

为已创建并预占库存的订单增加模拟支付确认能力，形成以下状态流转：

```text
PENDING（待支付）
  ├─ 确认支付 -> PAID（已支付）
  └─ 取消订单 -> CANCELLED（已取消）
```

## 接口

`POST /api/orders/{orderId}/payments`

无需请求体。

## 业务规则

- 首次支付只允许 `PENDING -> PAID`。
- 创建订单时已完成库存预占；支付只确认订单，不能再次扣减或释放库存。
- 重复支付返回已有 `PAID` 订单，不重复产生副作用。
- 已取消订单支付、已支付订单取消均返回 HTTP `409` 和业务码 `40902`。
- 支付和取消先锁定同一订单行，再使用带 `status = 'PENDING'` 条件的更新；竞争时只有一个状态转换能成功，后续请求读取到最终状态。

## 测试

`PaymentControllerTest` 覆盖：

- 支付成功后订单为 `PAID`，库存三项字段不变。
- 重复支付幂等，库存不变。
- 已取消订单支付被拒绝。
- 已支付订单取消被拒绝。
